# ClauseLens Database Design & Architecture

## 1. Architectural Overview

ClauseLens uses **PostgreSQL** as the single source of truth across all backend, NLP, personalization, and version-tracking workflows. Rather than splitting document metadata and structured analytics across heterogeneous stores, PostgreSQL provides:

- **Strict relational integrity** across users, profiles, documents, clauses, versions, diffs, and alerts.
- **Native decimal precision (`NUMERIC`)** for risk, severity, relevance, and magnitude scores.
- **Partial & composite indexing** tailored to dashboard, unread-notification, and scheduler polling queries.
- **Full Django ORM compatibility** for Member 2's Django REST Framework backend.

## 2. Normalization Decisions (1NF, 2NF, 3NF)

### First Normal Form (1NF) — Atomic Values & No Repeating Groups
- **Multi-value intended use tags:** Instead of storing comma-separated strings (e.g., `"Student, Freelancer"`) inside `user_profiles`, intended uses are stored atomically in `user_profile_intended_uses(user_profile_id, intended_use_id)`.
- **Original text vs. AI summaries:** Original legal text (`clauses.original_text`) and AI plain-language explanations (`clause_summaries.simple_explanation`) are separated so multiple summary versions/languages never duplicate legal text.

### Second Normal Form (2NF) — No Partial Key Dependencies
- Every table uses a single surrogate `BIGINT GENERATED BY DEFAULT AS IDENTITY` primary key (`id`), while natural uniqueness is enforced via `UNIQUE` constraints (e.g., `(document_id, clause_order)` on `clauses`, `(user_id, clause_id)` on `personalized_risks`, `(user_id, document_id)` on `monitored_policies`).
- Non-key attributes depend on the full entity key—for example, `relevance_score` and `why_it_matters` depend on the pair `(user_id, clause_id)`, not on `user_id` or `clause_id` alone.

### Third Normal Form (3NF) — No Transitive Dependencies
- **Lookup tables (`age_groups`, `jurisdictions`, `intended_use_categories`, `clause_categories`):** Descriptive metadata (`primary_framework`, `default_weight`, `min_age`/`max_age`) is stored once in lookup tables rather than repeated in `user_profiles` or `clauses`.
- **Shared public policies (`documents` + `monitored_policies`):** When multiple users monitor the same public policy URL, they subscribe via `monitored_policies(user_id, document_id)` pointing to one canonical `documents` row, avoiding duplicate copies of documents, clauses, and `policy_versions`.
- **User attribution:** `documents`, `personalized_risks`, and `notifications` reference `users.id` rather than duplicating user emails, names, or profile fields.

## 3. Relationships & Retention-Safe `ON DELETE` Rules

| Relationship | Cardinality | `ON DELETE` Behavior | Rationale |
|---|---|---|---|
| `users` → `user_profiles` | 1:1 | `CASCADE` | Profile context has no meaning without the user account. |
| `user_profiles` → `user_profile_intended_uses` | 1:N | `CASCADE` | Junction rows belong strictly to the profile. |
| `age_groups` / `jurisdictions` → `user_profiles` | 1:N | `RESTRICT` | Prevents deleting active reference categories. |
| `users` → `documents` | 1:N | `SET NULL` | Allows user account erasure without destroying shared public policies or historical evidence. |
| `documents` → `clauses` / `analysis_results` / `policy_versions` / `policy_changes` | 1:N | `RESTRICT` | Protects legal audit trails and version-diff history from accidental cascading deletion; user document deletion uses `is_deleted`/`deleted_at` soft deletion when history exists. |
| `clauses` → `clause_summaries` | 1:N | `CASCADE` | Summaries exist solely for their parent clause. |
| `users` / `clauses` → `personalized_risks` | 1:N | `CASCADE` | User-specific risk evaluations are purged if the user deletes their account. |
| `policy_versions` → `policy_changes` | 1:N | `RESTRICT` | Version snapshots referenced by diffs must remain immutable. |
| `clauses` → `policy_changes` (`old_clause_id`, `new_clause_id`) | 1:N | `SET NULL` | Allows clause cleanup while preserving change-log metadata. |
| `users` → `notifications` | 1:N | `CASCADE` | Deletes personal alerts upon account deletion. |
| `policy_changes` → `notifications` | 1:N | `SET NULL` | Preserves alert text even if a change row is archived. |
| `users` → `monitored_policies` | 1:N | `CASCADE` | Cancels user subscriptions when account is deleted. |
| `documents` → `monitored_policies` | 1:N | `RESTRICT` | Prevents deleting a document actively monitored by users. |

## 4. Indexing Strategy

| Index Name | Table & Columns | Purpose |
|---|---|---|
| `idx_users_email`, `idx_users_email_lower` | `users (email)`, `users (LOWER(email))` | Fast login and case-insensitive email uniqueness checks. |
| `idx_users_active` | `users (is_active) WHERE is_active = TRUE` | Partial index for active-account lookups. |
| `idx_documents_user_id`, `idx_documents_created_at` | `documents (user_id)`, `documents (created_at DESC)` | User document lists and recent document sorting. |
| `idx_documents_user_active_created` | `documents (user_id, created_at DESC) WHERE is_deleted = FALSE` | Primary "My Documents" page query without scanning soft-deleted rows. |
| `idx_documents_public_url` | `documents (policy_url) WHERE is_public_policy = TRUE` | Deduplicating public policy URLs when adding monitoring subscriptions. |
| `idx_clauses_document_id`, `idx_clauses_category_id` | `clauses (document_id)`, `clauses (category_id)` | Clause extraction retrieval and category filtering. |
| `idx_clauses_severity_score`, `idx_clauses_doc_severity` | `clauses (severity_score DESC)`, `(document_id, severity_score DESC)` | Top high-risk clauses across documents and per document. |
| `idx_clause_summaries_clause_id` | `clause_summaries (clause_id)` | Fast join from clause list to latest AI summary. |
| `idx_analysis_results_document_created` | `analysis_results (document_id, created_at DESC)` | Fetching latest completed analysis per document. |
| `idx_personalized_risks_user_relevance` | `personalized_risks (user_id, relevance_score DESC)` | Personalized clause ranking for a user without extra sort. |
| `idx_policy_versions_doc_seq`, `idx_policy_versions_content_hash` | `(document_id, version_sequence DESC)`, `(content_hash)` | Latest snapshot lookup and SHA-256 change detection. |
| `idx_policy_changes_versions`, `idx_policy_changes_type_detected` | `(old_version_id, new_version_id)`, `(change_type, detected_at DESC)` | Version-diff comparison and recent Added/Removed/Modified feeds. |
| `uq_notifications_user_policy_change` | `notifications (user_id, policy_change_id) WHERE policy_change_id IS NOT NULL` | Prevents duplicate alerts per user & policy change. |
| `idx_notifications_user_unread_recent` | `notifications (user_id, is_read, created_at DESC)` | Notification inbox and unread badge count. |
| `idx_monitored_policies_due_checks` | `monitored_policies (monitoring_status, next_check_at) WHERE monitoring_status = 'Active'` | Scheduler poll query for due policy checks. |

## 5. Cross-Team Module Data Contracts

- **Member 2 (Backend / Django REST Framework):** Owns Django ORM models and migrations (`managed = True`), JWT auth, and user-scoped query enforcement (`WHERE user_id = request.user.id`).
- **Member 4 (NLP & AI Processing):** Writes extracted rows into `clauses` (`category_id`, `clause_title`, `original_text`, `severity_score` in `[0, 1]`, `clause_order`), writes AI summaries into `clause_summaries`, updates `documents.processing_status`, and writes aggregate counts into `analysis_results`.
- **Member 5 (Personalization & Risk Analysis):** Reads `user_profiles` + `user_profile_intended_uses` + `clauses` and writes user-specific `relevance_score` (`[0, 1]`), `risk_level`, and `why_it_matters` into `personalized_risks`.
- **Member 6 (Version Tracking & Alerts):** Polls `monitored_policies` where `monitoring_status = 'Active'`, computes SHA-256 `content_hash`, inserts new `policy_versions` on hash mismatch, writes clause diffs into `policy_changes`, and generates deduplicated user alerts in `notifications`.

## 6. Security, Privacy, Backup & Recovery

1. **Least-Privilege Roles (`scripts/setup_roles.sql`):**
   - `clauselens_app`: `SELECT, INSERT, UPDATE, DELETE` only (no `DROP`, `TRUNCATE`, or DDL in runtime app sessions).
   - `clauselens_readonly`: `SELECT` only for reporting/audits.
2. **Credential Hygiene:** Passwords and connection strings live exclusively in `.env` (git-ignored) and runtime environment variables; `.env.example` contains placeholders only.
3. **Password Hashing:** `users.password` stores Django PBKDF2/Argon2 hashes (`CHAR_LENGTH >= 20` check prevents short plaintext inserts).
4. **Profile & Document Isolation:** All user-facing queries filter by authenticated `user_id` or `is_public_policy = TRUE`.
5. **Backup & Recovery Plan:**
   - Daily logical backups using `pg_dump -Fc -Z 6 clauselens_db > clauselens_$(date +%F).dump` stored encrypted off-host.
   - Continuous WAL archiving for Point-in-Time Recovery (PITR) in production.
   - Monthly restore drills into a staging instance followed by `scripts/verify_database.sql`.
